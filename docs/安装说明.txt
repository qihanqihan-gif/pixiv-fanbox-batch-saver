画师文件夹下载器 v0.3.38 — 安装与使用说明
============================================================
（v0.3.34 起由「Fanbox 文件夹下载器」改名：现在同时管 Fanbox / Pixiv 画师与 Pixiv 收藏，
  功能不变。手机上的安装目录名仍是 /sdcard/Download/FanboxFolderDl/，不必跟着改，
  改了反而要重新 Load unpacked 一次。）
（v0.3.38 起扩展自带图标（icons\ 目录，16/32/48/128），装好后工具栏/扩展列表里
  是「蓝文件夹 + 向下箭头」，不再是系统默认的拼图块。）
（本文自 v0.3.11 起累积更新，界面细节以实际页面为准。）

一、推荐安装方式：Load unpacked（已在真机验证可用）
------------------------------------------------------------
1. 把本包里这些文件（**含 icons 子目录**）解压到手机 /sdcard/Download/FanboxFolderDl/
     manifest.json  app.html  app.css  app.js
     content.js  sw.js  pixiv.js  pixiv-line.js  rules-pixiv.json
     icons\icon16.png  icons\icon32.png  icons\icon48.png  icons\icon128.png
     安装说明.txt（这个不装也行）
   ※ icons 目录缺了扩展会加载失败（manifest 里登记了图标路径）
2. Bare Browser → 地址栏输入 chrome://extensions → 右上 More → Load unpacked
3. 选 /sdcard/Download/FanboxFolderDl
4. 打开任意 fanbox 页面，左下角会出现
     「📁 下载本篇（投稿ID）」「📁 下载该画师全部投稿」
   打开任意 pixiv 作品页 / 画师主页 / 小说页，也会出现
     「📁 下载本篇（作品ID）」「📁 下载该画师全部作品」
   也可以直接访问
     chrome-extension://<你的扩展ID>/app.html
   （注意 ID 以你实际装出来的为准，见第三节）


二、Pixiv 支持范围（v0.3.x 起）
------------------------------------------------------------
已支持，全部实测跑通过：
  · 多页插画 / 漫画   → 001.png / 002.jpg … 每页一条，取的是画师上传的
                        urls.original（不缩放、不重编码）
  · 动图 ugoira       → 001_ugoira.zip（originalSrc，1920×1080 原始包，一个文件）
                        ＋ 动图信息.json（145 帧的文件名与每帧延时、mime、帧数）
                        ※ 动图**不拆帧**：帧就在 zip 里，播放器按 动图信息.json 的延时放。
                        ※ pixiv 没有 gif 可下 —— 它的动图原始文件就是这个 zip。
  · 小说              → 投稿信息.txt ＋ 正文.txt（正文由 HTML 转纯文本）
  · 每件作品一个文件夹、总文件夹用画师名、_清单/_索引/_进度/断点续传/补漏
    与 Fanbox 那一套完全共用

已知限制：
  · 小说只存文字，不存插画封面
  · 动图存 zip + 延时表两份小文件（约「zip 大小 + 8 KB」），不转换、不重新编码
  · pixiv 的「批量作品列表」接口会返回 400，所以枚举只取 id 列表
    （一次请求拿全部），标题/页数在逐件处理时现取

取原图的技术要点：i.pximg.net 不发 CORS 头、且要求 Referer 为
https://www.pixiv.net/，所以图片由扩展页面去取（host_permissions 绕开 CORS）
＋ declarativeNetRequest 规则补 Referer（rules-pixiv.json）。
这两个文件（pixiv-line.js、rules-pixiv.json）缺一个，pixiv 就下不了。


二·补、三种下载模式与收藏导出（v0.3.32 起，v0.3.38 现状）
------------------------------------------------------------
界面上方三张卡就是三种模式，点哪张就切到哪张：

  1) FANBOX 画师  —— 填 creatorId（主页 @ 后面那段）或整条主页链接
  2) PIXIV  画师  —— 填画师 uid 或主页链接（和 Fanbox 不是同一套编号）
  3) PIXIV  收藏  —— 读某个账号的收藏列表：
                     · 账号框留空 = 当前登录账号
                     · 填数字 uid = 那个账号的公开收藏
                     · 「收藏结构」选 平铺 或 分组（只改目录层次，不改下载内容）

收藏模式的落点：
  · 平铺：<你选的目录>/_我的收藏 (PIXIV)/<日期-作品id-标题>/
  · 分组：<你选的目录>/<画师名> (PIXIV)/<日期-作品id-标题>/
          组按件数从多到少排；跑的过程中会临时借用那个画师目录，跑完还原。

导出 / 导入枚举 JSON（模块 1 底部两个按钮）：
  · 「导出枚举 JSON」把这一轮枚举到的清单存成文件，方便换机/换扩展 ID 后
    不用重新联网枚举：收藏模式导出 pixiv_收藏_<uid>_<篇数>篇.json，
    画师模式导出画师清单。导出的是「枚举结果」，不含任何登录信息。
  · 「导入枚举 JSON」把清单灌回运行通道，接着下。
    收藏模式下这个按钮是禁用的（收藏清单以实时枚举为准，避免导错账号）。
  · 收藏枚举跑完会把整份清单记在本地（键 posts:pixiv:fav:<uid>），
    换机会清掉——清掉就用「导出」把清单带过去。

三、扩展 ID 与 CRX
------------------------------------------------------------
- 扩展 ID 由「加载目录的绝对路径」决定：换目录或换机器，ID 就不同，
  localStorage（枚举缓存/进度/表单）和 IndexedDB（记住的目录）会全部作废。
- 仓库里不带 CRX，也不带 .pkcs12/.pem 私钥。要自签就用你自己的密钥：
    chrome.exe --pack-extension=<仓库>\extension --pack-extension-key=<你自己的>.pem
  换密钥 = 换扩展 ID，进度和记住的保存目录都不通用。
- 自签 CRX 的安装限制（供参考）：
    1) 安卓 Chrome 没有安装 CRX 的入口，手机上只能用第一节的 Load unpacked。
    2) 桌面版 Chrome/Edge 不接受拖拽安装自签 CRX；只有企业策略下发
       （ExtensionInstallForcelist + 更新地址）或命令行 --load-extension 加载解压目录。


四、升级时的固定步骤
------------------------------------------------------------
1. 覆盖 /sdcard/Download/FanboxFolderDl/ 里的文件
2. 重新加载扩展：
     chrome://extensions → 找到本扩展 → 点 ⟳
   ⚠ 实测坑：在手机上点 ⟳ 有时会**卡在 reloading 状态**（扩展变灰、版本号
     还显示旧的）。这时别再连点，直接强制关掉 Chrome 再打开
     （系统设置 → 应用 → 强行停止 Bare Browser），扩展就会正常加载。
3. 重新打开工作台（旧标签页里跑的还是旧代码，不会自动更新）
4. 点「开始」→ 系统会弹一次「允许此网站修改文件？」，点允许
   （每次重新加载扩展后都会再问一次；弹窗期间**屏幕不能熄灭**，
     否则会超时报「等待授权超时 30 秒」）


五、使用要点
------------------------------------------------------------
- 屏幕保持亮着；页面不要长时间切到后台。
- 「总文件夹名」留空 = 用画师名（pixiv 用 /ajax/user 接口取，取不到才退回 uid）。
- 「附件/压缩包」默认不勾（fanbox 的压缩包体积很大）。
- 「跳过已存在」建议一直勾着：已下好的文件会跳过，只补缺的。
- 中断后直接再点「开始」即可，不用从头来。
- 改过「选项」里的勾选（附件/封面/正文）等于换了一套进度，之前的完成标记
  不会沿用 —— 想接着跑就别动那几个勾。
- pixiv 与 fanbox 的枚举/进度存档现在按站点分开存（pixiv 的键带 pixiv: 前缀），
  同一个数字 id 不会互相覆盖。

总文件夹里这几个文件不要删：
    _清单.jsonl      记录每个文件的字节数，续跑靠它判断半截文件
    _清单.bak.jsonl  上一版备份，主清单写坏时自动回退
    _失败清单.json   本轮失败的文件清单，便于事后排查
    _进度.json       本轮统计
    _投稿列表.json   本轮用到的投稿清单


六、完整性自检（可选，进阶）
------------------------------------------------------------
fanbox 的文件服务器不返回 Content-Length，所以只能靠「格式终止符」判断完整性：
  JPEG 必须以 FF D9 结尾
  PNG  必须以 IEND 结尾（49 45 4E 44 AE 42 60 82）
  ZIP  必须以 EOCD（50 4B 05 06）结尾，且「EOCD 起点 + 22 + 注释长度」要等于文件末尾
pixiv 的 img-original 有 Content-Length，走字节数比对；ugoira 的 zip 两种校验都有。

需要人工批量核查时（需装 adb）：

  adb shell 'f=/sdcard/Download/所选目录/画师名/某篇/001.jpeg; \
             tail -c 2 "$f" | od -An -tx1'

输出不是 ff d9 就是被截断的文件。


七、v0.3.11 起的一个行为变化（看到「重下一次」别慌）
------------------------------------------------------------
判定「磁盘上这个文件算不算下完」的规则变了：

  · 清单里记着这个文件的字节数   → 只比大小（老规则，不变）
  · 清单里没记录（首轮 / 清单损坏 / 上一轮收尾前被杀）：
      - jpg / jpeg / png / gif / zip → 验格式尾标，验过就跳过
      - 其它格式（psd / psb / mp4 / pdf …）→ **重下一次**

为什么：这些格式没有统一的文件末尾标记，没法确认完整性。以前的做法是
「验不了就放行」，结果进程被杀留下的半截 .psd 会被当成已下完、**永久跳过**，
续跑多少次都修不回来。现在改成宁重下一次。

所以偶尔会在日志里看到：
    · 001_xxx.psd 存在但无法校验完整性（该格式没有尾标），重下一次
这是正常的，不是报错，也不会重复太多 —— 下完一条就记进清单，下次就只比大小了。

八、v0.3.12 起：选完目录就知道里面有什么
------------------------------------------------------------
1. 选完「保存到」目录会自动扫描：列出每个画师文件夹的站点（FANBOX / PIXIV）、
   已完成篇数、文件数、体积。点「继续这一位」就直接续跑——不用再手填画师 ID，
   也不会重下已有文件。
2. 新建的画师文件夹会自动带站点后缀：`某画师 (FANBOX)` / `某画师B (PIXIV)`，
   并在文件夹里写一份 `_站点.json`。原因：pixiv 的 uid 与 fanbox 的 creatorId 是
   两套编号，画师显示名撞了就会写进同一个文件夹、清单混在一起算不清。
3. 老文件夹（纯画师名、没有后缀）不会被改名——安卓下 FSA 没有原子改名，改名等于
   整个目录复制一遍。沿用时会自动补写 `_站点.json`；卡片上显示「未标记」的，
   可以点「标记为 FANBOX / PIXIV」，也只是补一个文件，名字不动。
4. 进度以文件夹为准：`_清单.jsonl` 里有记录的篇按「已完成」处理，
   换手机、重装扩展、清掉浏览器数据之后也不会白跑一遍。另外会优先用文件夹里的
   `_投稿列表.json` 顶替枚举，换机后不联网枚举也能直接续跑。
5. 想重新扫一遍，点扫描区右上角的「重扫」（页面刷新后需要重新授权一次目录，
   这是浏览器的规矩，不是故障）。

6. 卡片上的「文件数 / 体积」是**累计**口径（清单里所有记录的合计），不是本轮下了多少；
   只有 `_进度.json` 里还记着 `lastRun` 供排查用。
   注：如果只跑过一次「单篇模式」，卡片的篇数会显示成「N 篇已完成」而不是「N/M 篇」，
   因为那次运行的 total 只有 1 篇。

本功能在 v0.3.13（扩展）与 v0.1.5（油猴版）里是同一套逻辑；v0.3.12 是同一功能的中间版本。
